# Learning contract

## Daniel's responsibilities

- Attempt each `TODO(Daniel)` before requesting a completed solution.
- Use documentation and ask for hints, but disclose coding-agent assistance.
- Run tests and read the failure before changing code.
- Explain every critical function in his own words.
- Keep a short reflection in `docs/PROGRESS.md`.

## Tutor responsibilities

- Explain only the concepts required by the next feature.
- Connect unfamiliar Python ideas to Daniel's Android/Kotlin experience.
- Review actual code and test evidence.
- Identify the smallest important correction first.
- Add evaluation, failure analysis, privacy, latency, and cost as AI features appear.
- Do not mark a lesson complete because a video was watched.

## Definition of complete

A task is complete when:

1. Required behavior works.
2. Tests cover normal, boundary, and failure cases.
3. Daniel can explain the code and one alternative.
4. Important work can be reproduced without copying the earlier solution.
